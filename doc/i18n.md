# UI internationalization (i18n)

The board UI (`ui/`) renders every user-facing string through `i18next` with
natural-language keys: the English text is the key, and each locale file maps
those keys to translations. English needs no catalog; a missing translation
falls back to the key itself.

## How it works

- `ui/src/i18n/index.ts` initializes `i18next` synchronously (no suspense) and
  exports `t`, `useTranslation`, `currentLocale`, and the `i18n` instance.
- `ui/src/i18n/locales.ts` lists the available locales (`en`, `pt-BR`), resolves
  the initial locale (stored preference, then browser languages, then English)
  and persists the choice in `localStorage` under `paperclip.locale`.
- `ui/src/i18n/locales/pt-BR.json` is the Brazilian Portuguese catalog: a flat
  object of `"English key": "tradução"`.
- `ui/src/i18n/locale-validation.ts` validates catalogs: placeholders must match
  the key, values are plain text (no HTML, scripts, event handlers, or URLs that
  the key does not contain), and length is capped.
- The language can be changed from the account menu in the sidebar or from
  Profile settings; the page reloads with the new locale. Under Vitest the
  locale is forced to English so tests keep matching the source strings.

## Writing strings

```tsx
import { t } from "@/i18n";

<Button>{t("Save changes")}</Button>
<p>{t("{{count}} agents selected", { count })}</p>
```

- Use `t("…")` from `@/i18n` in components, hooks and `lib/` helpers. When a
  file already binds a local `t`, import it as `translate`.
- Keys are the English sentence, in sentence case, including punctuation.
  Interpolate values with `{{name}}` placeholders; never concatenate.
- Plurals use two keys chosen in code: `n === 1 ? t("{{n}} run", { n }) :
  t("{{n}} runs", { n })`.
- Translate display text only. Never wrap prompts, agent instructions, tool or
  API payloads, shell commands, environment variable names, file names, CSS
  classes, identifiers, or anything compared against server data.
- Strings that look like code are kept untranslated on purpose (see the skip
  list used by the codemod).

## Scripts

```sh
pnpm check:i18n                    # coverage, stale keys and invalid values per locale
pnpm check:i18n -- --strict        # non-zero exit on any problem (CI friendly)
pnpm check:i18n -- --locale=pt-BR --untranslated=/tmp/missing.json
pnpm i18n:codemod -- --objects --vars --returns --ts --report=/tmp/report.json
pnpm i18n:codemod -- --apply --objects --vars --returns --ts --skip-keys=skip.json
```

`scripts/i18n-check.ts` reads every `t("…")` call in `ui/src` and compares it
with each locale file. `scripts/i18n-codemod.ts` wraps untranslated display
strings in `t()` (JSX text, display attributes, labelled object properties,
display helper returns, template literals with plural branches) and can revert
keys with `--revert=keys.json`. Both share `scripts/i18n-lib.ts`.

## Adding a locale

1. Add the code to `AVAILABLE_LOCALES` and `LOCALE_LABELS` in
   `ui/src/i18n/locales.ts` and import its JSON into `localeMessages`.
2. Run `pnpm check:i18n -- --locale=<code> --untranslated=missing.json` and
   translate the listed keys.
3. Run `pnpm check:i18n -- --strict` until it reports no invalid or stale keys.
